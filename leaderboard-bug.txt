To fix the English names on the minting ranking boards, we must ensure that when func_C4B94F writes the default strings into SRAM, it loads English tile data rather than the original Japanese. The clean way is:

In text/leaderboard.asm, replace each Text1312–Text1333 ASCII string with a .dw block of 16-bit tile codes (the same format the Japanese ROM used: eight words per name). This wraps each English name in the exact encoding the renderer expects.

You can extract the tile values from your existing LeaderboardNames table (which already renders correctly) or manually translate the characters to their SNES tile IDs.

Leave TextPointerTable untouched; it still produces the low 16-bit offsets for func_C4B94F, which now resolve to the new tile-coded English block.

No code changes are needed—the key point is supplying the data in the original 16-bit tile format so the existing pointer logic works for the English defaults.


What the original game does
When you “mint” a ranking board (e.g., the first time you die in a dungeon), the SNES code calls func_C4B94F (bank 04).
That routine looks up a text ID in TextPointerTable, switches the data bank back to the original script bank, and streams 16-bit tile values straight into SRAM at $7ECA66.
A second helper (func_C4BF88) immediately reads those 16-bit glyphs from SRAM to populate the on-screen list. In the Japanese ROM this chain is perfect because the table pointed to Japanese script blocks already stored in tile format.
What the fan translation changed
To display English strings elsewhere, the patchers rewrote the script files (text/leaderboard.asm) using ASCII. The onscreen code we see in func_C678AE uses an English table (LeaderboardNames) to render Impasse Valley correctly.
However, when the game mints other boards, it still runs through the original func_C4B94F → TextPointerTable → Japanese bank pipeline. Since those entries were never re-encoded as tile data, the first-time board defaults come out as Japanese glyph codes (and look garbled on screen).
Why the bug persists
TextPointerTable in the translated project still contains the same 16-bit offsets as the Japanese ROM, and the helper routines still switch to the unmodified text bank.
The English strings you see in text/leaderboard.asm live elsewhere in the ROM (and are ASCII, not tile-coded), so the minting code never touches them.
As a result, SRAM keeps receiving the original tile data.
Fixing it requires one of two approaches
Rewrite the data. Replace the Text1312…Text1333 blocks with tile-encoded English strings (8 words per name, padded to match the SNES font). Once the table points to tile-formatted English data, func_C4B94F/func_C4BF88 work unmodified.
Patch the minting path. Keep the ASCII strings but add a helper in func_C678AE that, right after func_C4B94F returns, copies the English tile data (e.g., from LeaderboardNames) into $7ECA66. That overwrites the Japanese defaults without changing the table.
The key limitation is that the minting routines expect tile-formatted data; merely translating text/leaderboard.asm to ASCII doesn’t change what TextPointerTable points to.
