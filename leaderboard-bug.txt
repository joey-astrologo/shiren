The leaderboard bug

The leaderboards are bugged in game. In the fan translation, when impasse valley is minted, it is read from 
the function LeaderboardNames in ./text.asm

The function in ./code/bank_06.asm has modified logic to read the names from there instead of TextPointerTable 
where the translated names are.

There are Text1312 to Text1326 for Impasse Valley, Text1327 for Food God Shrine, Text1328 to Text1332 for Wall Scroll Cave, and Text 1333 for Final Problem


High‑Level Differences

Redirects the name source: Main streams Text1312–Text1333 from the script. English‑fixes detours the text engine’s $FF end‑of‑row handler to supply a pointer to a default‑names table instead of continuing to read the script stream.

Uses a helper to map text IDs: English‑fixes adds a small routine (in the text bank) that takes the current text ID, subtracts a base (e.g., $6007 for Text1312), multiplies by 16, and returns a 24‑bit pointer to the Nth default row. The text streamer then copies exactly 16 bytes from that row into SRAM.

Stages defaults in WRAM at boot: In addition to (or instead of) a ROM table, English‑fixes pre‑loads a small default‑names table into WRAM ($7E:B000… ranges). A companion helper then maps the current board to B000/B100/B200 and an offset within that block. Main does not stage any leaderboard data at boot.

Bypasses Text1312–Text1333 contents: Main expects those script entries to carry the pre‑encoded glyph bytes for each name. English‑fixes ignores them when minting, using the table/lookups described above.

Fixed row length + terminator handling: English‑fixes forces a 16‑byte copy (single name row), and relies on the streamer’s control‑code terminator ($FFFF) after the copy. Main reads the script stream until it sees $FF (per row) and then continues.

Concrete Code Changes (English‑fixes vs Main)

$FF handler detour (text engine):

Main: func_C4BA53 just sets up a copy from the current script position and streams bytes until it hits $FF.
English‑fixes: inserts a jsl to a helper (often seen as func_FE01DE) that:
Reads the current text ID from the script engine’s stream pointer (DP).
Computes a row index (ID − $6007) and offset (index << 4).
Returns a pointer in wTemp02/03 to the default names table.
Sets a copy length of 16 bytes for the subsequent loop.
WRAM staging + index mapping:

Main: no boot‑time copy; names come from ROM script at mint time.
English‑fixes: at boot, uses MVN/MVP to copy a default‑names block into WRAM (e.g., $7E:B000). Another helper (often func_FE01B6) maps the ID to B000/B100/B200 and applies the row offset (index << 4) to return the correct WRAM address for minting.
Scoreboard UI pre‑setup:

English‑fixes sets up and touches the $B360xx UI region early (bank $B3 tables), preparing slots that the text/scoreboard routines reference. Main does much less here and relies on the normal script path to populate what’s needed only when a board is viewed/unlocked.
When Defaults Get Used

Main: Defaults are copied from ROM script into SRAM only when the board legitimately unlocks; Text1312–Text1333 define the canonical bytes.

English‑fixes: Defaults come from the table (ROM or staged WRAM) whenever the scoreboard handler hits the patched $FF path. The timing and source are decoupled from the script, so the mint can happen outside the original unlock moment if the hook is engaged (e.g., when the ranking UI initializes).

Why They Did It

The original Japanese default rows were stored as glyph codes, not normal text. English‑fixes chose to centralize those “glyph rows” in a small table and redirect the text engine to copy from there, rather than forcing the script (Text1312–Text1333) to hold non‑text data. That avoided touching lots of script entries and made the defaults easy to manage in one place.
Implications

Good: Compact, single‑source glyph rows; simpler to localize names without worrying about the script encoder; controlled 16‑byte copies.

Risk: If any code still reads the original WRAM staging (instead of the updated table), you get mixed sources. If the table’s bytes aren’t true glyph codes, the renderer draws the wrong tiles. If the detour runs outside of unlock time, defaults get pasted when they shouldn’t. All of these are differences from main’s simpler “read text entry until $FF” behavior.
